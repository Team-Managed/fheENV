# CI/CD Integration

Production automation should use AWS KMS or a protocol-v1 external signer. Long-lived raw Ethereum
keys are not accepted by production mode.

## AWS KMS with workload identity

Create an `ECC_SECG_P256K1` KMS key, derive and record its Ethereum address, then grant that address
only the required fheENV environment access:

```bash
fheenv team add --member 0xKMS_ADDRESS --env production
fheenv signer configure aws-kms \
  --key-id arn:aws:kms:REGION:ACCOUNT:key/ID \
  --expected-address 0xKMS_ADDRESS
```

Use GitHub OIDC or the equivalent CI workload identity. The AWS SDK default credential chain
consumes the short-lived role credentials:

```yaml title=".github/workflows/deploy.yml"
permissions:
  contents: read
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ vars.FHEENV_AWS_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}
      - name: Start application
        env:
          FHEENV_PINATA_JWT: ${{ secrets.FHEENV_PINATA_JWT }}
        run: fheenv run --env production -- npm start
```

The local KMS policy permits only the configured chain, registry, known function selectors, zero
native value, and bounded gas/fees before calling KMS. IAM and organization controls remain the
outer authorization boundary.

## External custody systems

Fireblocks, Turnkey, MPC services, Azure/Google/Vault adapters, and internal signers can implement
the external signer protocol:

```bash
export FHEENV_EXTERNAL_SIGNER_CUSTODY=/opt/fheenv/custody-signer
fheenv signer configure external \
  --provider custody \
  --expected-address 0x...
```

The wrapper executable receives one bounded JSON request on stdin and returns one JSON line on
stdout. Keep provider tokens inside its workload identity or an allowlisted environment. Payloads
and credentials must never be command arguments.

## Non-signing credentials

Headless jobs may use explicit `env://VARIABLE` references for Pinata or credential-bearing RPC
endpoints. Native keyrings fail closed when no desktop Secret Service exists; fheENV does not
silently fall back to environment variables.

<Callout type="warn">
  Grants do not expire automatically. Remove a retired worker and rotate with the source environment
  file. `--no-rotate` leaves its current FHE handles decryptable.
</Callout>

```bash
fheenv team remove --member 0xOLD_WORKER --env production --file .env
```

If revocation succeeds but rotation/regrant fails, the command exits non-zero. Run the printed
idempotent recovery command. Retain the on-chain receipt, provider audit entry, CLI audit export,
review approval, and validation result under your organization's retention policy.
